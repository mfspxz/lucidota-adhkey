# Graphical Intuition — design

**Source:** Zackary's synthesis, 2026-10-06. Status: DESIGN.
The engineering target is NOT "turn hunches into cautious hypotheses."

## The claim

> When a hunch fires, the graph has already done compression, association,
> anomaly detection, topology matching, prior retrieval, and causal
> inference before conscious articulation.

The system must externalize that mechanism, not weaken it:

```
WORLD → observations → latent pattern recognition → graph activation
    → structural correspondence → candidate explanation
    → high-confidence hunch → targeted investigation
```

Investigation is downstream of the hunch, not what creates it.

## Graphical Intuition (the primitive)

A computationally recoverable phenomenon:

```
many weak observations → latent graph → relationships activate
    → structural mismatch appears → known shapes resonate
    → candidate explanation emerges → confidence → target selection
```

Relationships, not observations, are the unit. A uranium reading alone is
meaningless; conductivity + boundary + fault + alteration + depth lights
up the model. A weird commit + unexpected dependency + authorization path
+ previous failure shape + stated doctrine lights up "authority
substitution again."

Conventional ML: features → classifier.
This: observations → heterogeneous relationship graph → activation /
structural matching → latent configuration → hunch.

**The graph does the inference.** Project Shape MCP is the persistent
external substrate for the implicit graph; Failure Shape is another
layer; AdhKey gives epistemic provenance; Court supplies falsification.

## Five-layer architecture

```
REALITY → OBSERVATIONS → RELATIONAL GRAPH (entities, events,
constraints, temporal relations, causal candidates, analogies,
contradictions) → graph activation → HUNCH ("something here doesn't
fit") → targeted search → INVESTIGATION (discriminating evidence,
independent corroboration) → ESTABLISHED STRUCTURE → PROJECT SHAPE /
FAILURE SHAPE → COURT → FEEDBACK
```

## The 98% claim, made testable

Don't assume the hunches are right. Measure them. Every hunch records:

- Hunch ID, timestamp
- initial observations
- activated graph nodes + relationships
- candidate conclusion
- confidence
- what would falsify it
- investigation chosen
- eventual outcome

Metrics:

- **Hunch precision** = correct hunches / investigated hunches
- **Graph advantage** = performance with prior graph / performance
  without prior graph
- **Search efficiency** = information gained / investigation cost

If hunches run ~98% precision over a defined corpus, that's an
extraordinary engineering result. If the system reconstructs even part
of the graph activation, that's more valuable than a chatbot memory.

## Multi-ontology relationships

No single ontology. Permitted relationship types:

CAUSES, PRECEDES, CONTRADICTS, CORRELATES, CONTAINS, DEPENDS_ON,
AUTHORIZES, WITNESSES, RESEMBLES, DERIVES_FROM, VIOLATES, EXCLUDES,
EXPLAINS, PREDICTS

The load-bearing distinction: **RESEMBLES ≠ CAUSES.** The mind says "I've
seen this shape before"; the system records RESEMBLES(FS-017,
observation), never auto-promoting to CAUSES. Epistemic discipline
preserving intuition speed without its failure modes.
