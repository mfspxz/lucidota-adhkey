# REDTEAM-003 — TIG Operational Layer

## 9. CLAIMED → ESTABLISHED laundering
**BROKEN.** The seam is not a code path in TIG — it is the *reduce()* signature. TIG design says ESTABLISHED = Statement{predicate: EstablishedUnder, evidence:[witness statements]}. Round-2 established that `reduce` ignores evidence entirely and `policy: String` is decorative. Concretely: heuristic engine (issuer = `heuristic-X`) emits `ProbablySameAs` with `evidence: [run_ref]`. Any establishment path that filters on `evidence.len() > 0` — or any deployer who writes it that way because the schema said "evidence is a Vec" — promotes the heuristic. The doctrine forbids it; the *mechanism does not enforce the doctrine*. Witness statements and heuristic-run-refs share the same `EvidenceRef` shape. There is no type-level distinction between "a statement that counts as evidence" and "a reference to a process that produced a candidate." The attack is not injection — it is a well-intentioned developer writing the obvious loop. **Fix is type-level: `WitnessRef` must be a distinct type from `HeuristicRunRef`, and the establishment constructor must accept only the former.** Doctrine #5 is not a mechanism until the type system refuses the alternative.

## 10. Weight laundering via traversal priority
**BROKEN.** Concrete attack: adversary controls heuristic signals that weight E_claimed(A,B). Witness collector has bounded time T. Collector uses weight-priority traversal. Attacker saturates its own high-weight paths (ghost-clumped) so the collector's T budget is consumed reaching attacker-controlled witness candidates; legitimate witness paths (lower weight) time out. The collector returns `W = {weak witness A′}` instead of W's honest result. The algebra holds (`W` is non-empty, `P` signs off), but *which W was collected* was adversarially determined by claimed-side weight. Kill-target 10 predicted exactly this. Design response: if weight only influences order, then order must be *complete within T* regardless of input, or T must be a function of the subgraph, not the weight ordering. Either the collector is exhaustive (kills the "priority" optimization that motivated weight) or the collector is bounded-and-sampled (weights decide inclusion → promotion channel). **The design cannot have both 0.0–1.0 weight granularity and an epistemic firewall.** Pick one. Weight should be *quarantined to the CLAIMED tier entirely* — not visible to the collector at all. Then heuristic discovery feeds *existence* of candidates, and *collection* is ordered by witness-independence metrics (doctrine #4), not by claim strength.

## 11. Invalidation race — TOCTOU on revocation
**BROKEN by the design's own admission.** Idea #2 says "same clock cycle is not a distributed primitive... MUST be specified before this claim is made." That is a confession, not a mitigation. Concrete: YubiKey key revoked at commit C. Lease L exercised at C+ε. If L's evaluation read `witness_status: VALID` at any cached view pre-C, authorization fires on dead authority. **O(1) retraction is not achievable for active leases without eager binding** — the lease must store the *set of witness root IDs* it depends on, and *every exercise* must re-check *those root IDs' current status* (doctrine #2: freshness bound). Then revocation is O(1) at the *revocation site* (flip the root node) but O(dependent leases) at *exercise time* — and the truth is: **there is no O(1) anywhere for authorization safety**, only O(1) for marking, and O(1) per-exercise for checking. The "O(1) retraction" claim is theater unless re-read to mean "O(1) to mark revoked, O(1) per-exercise to detect." Same clock cycle is not required — the freshness bound is. Specify the bound as max(exercise_interval) or the claim dies.

## 12. Ghost clumping + one weak witness
**BROKEN as stated, and the target correctly predicted this.** The firewall is an *architectural* claim ("no heuristic path to authority") but the actual gate is a *policy* claim ("P accepts only strong witnesses"). Under adversarial composition (per doctrine #4), the attacker does not defeat either alone — they exploit the policy's accepted witness set. If P accepts email OTP, SMS, or self-asserted OAuth (all standard for reasons of UX), then clumping + OTP = promotion. The design's own "sharp edge" note is correct and incomplete: **the protocol must specify a witness-independence lattice**, not leave it to deployers. Concretely, a witness type must be classified by (a) what trust root issues it, (b) what adversary can forge it at what cost, (c) whether it is co-located with any other accepted witness in the same trust domain. A HIGH-assurance policy that accepts OTP is not a policy — it is a ritual. **Minimum protocol artifact: a signed witness-class registry, itself subject to doctrine #1.** Without it, "policy P" is a `String` (round-2 finding) with a castle painted on it.

## 13. EQL tier confusion
**BROKEN.** Idea #4 admits the planner is a trust boundary and that "tier is a string parameter." Concrete: developer writes `MATCH (a)-[e:RESOLVES_TO {tier: 'ESTABLISHED'}]->(b)` where `tier` is a bind variable from request header. `Authorization: Bearer … tier=ESTABLISHED`. Planner defaults unknown tier to highest-trust (to "fail open for UX") or string-compares against a schema constant — either is exploitable. **Fix is not "use an enum."** The query must not carry the trust assertion at all. The *reducer* produces a typed graph where CLAIMED and ESTABLISHED edges are *physically different edge types* in the store, and the query language has *no syntax to cross* from a CLAIMED-resolved node to an authority-bearing one. EQL as designed encodes the trust tier as a *filter* — filters are attacker-influenceable. It must be a *compile-time resolution of edge kind*, and the developer's constant must be burned into the compiled plan and signed. Otherwise the tier is CSP-style decorative.

## 14. Primitive composition seams
**BROKEN at the sharpest seam, as predicted.** `au` receives "an E_established subgraph." Round-2 already established `reduce` accepts a forest and is order-dependent. If `au` trusts a caller-supplied subgraph, doctrine #1 is violated *and* doctrine #5 is violated (the caller decided what was established). The invariant is not "evaluator reduces the subgraph" — that is just declaring the fix without the mechanism. The mechanism: **`au` must accept only `(genesis_id, state_version, evaluation_receipt_id)` and reduce internally from the log.** Any API shape where the caller materializes nodes into `au` is the vulnerability. Enumerate the other seams: `evd → po` (who signs the witness-class registry?), `id → re` (what makes a key *an* identity node vs *authorized by* one — round-2 #6), `st → au` (state version is *which* version — global, per-subject, or per-policy?). Every one of these is a doctrine-#1 replay point. **The design does not have "seams to be enumerated" — it has "unspecified interfaces where the doctrine can be reversed by the caller."**

# NEW: findings the kill-targets missed

**NEW-1. The "authorization layer" that round-2 demanded has no home in TIG.**
Round-2 concluded: "authorization layer between authenticate and reduce." TIG's layer model is CLAIMED → ESTABLISHED → AUTHORIZED. That is a *promotion* axis, not an *authorization-to-act* axis. The round-2 gap ("Alice said X" vs "Alice was authorized to say X") is *orthogonal* to TIG's ternary. Concretely: a statement can be AUTHORIZED-tier (an active capability lease) and still be issued by an unauthorized issuer. TIG's ternary does not cover "the statement is epistemically fine but the issuer was not permitted to emit it." **TIG needs a fourth axis or an orthogonality declaration.** The design currently quietly assumes issuance-permission is handled below, but the whole reason round-2 broke is that it was assumed below and nothing was there.

**NEW-2. "O(1) retraction" and the DAG more generally contradict doctrine #2.**
Doctrine #2: local state may not claim to know a remote fact without witness/version/freshness bound. A cached ESTABLISHED edge *is* local state claiming to know a remote fact (witness validity). Its freshness bound must be *recorded on the edge* (`valid_until`, `state_version_at_establishment`). TIG's ESTABLISHED edge carries `version: V` — good — but no *expiry*. So the invalidation race isn't only at revocation; it is at *every_use* of any established edge, because the edge's assertion "W was valid" decays. This is the same class as round-2 #6 (stale-snapshot key resolution). The design does not have a freshness discipline for its own derived state.

**NEW-3. The 15-primitive mapping's `evd` (Evidence) row inherits every round-2 evidence failure.**
`evd` = "Witness nodes: signed EATs, passkey assertions, verified OAuth receipts." Round-2 broke #7 (recursion/termination) and #8 (policy) without TIG. TIG's mapping does not repair them — it *names* the primitive that must repair them. The mapping table is a *dependency list*, not an architecture. Anyone reading it as "we have witnesses, so we have evd" is reading doctrine #1's violation into the diagram.

**NEW-4. EQL's "tier: ESTABLISHED" is indistinguishable from a cached authorization.**
The example query returns `b.payout_account` under `tier: ESTABLISHED + policy: FINANCIAL_DISBURSEMENT_v2 + witness_status: VALID + not_after > now()`. That is not a heuristic query with a high trust tier — that is `can subject X move money to Y`, i.e. AUTHORIZED-tier. The example *conflates* the ESTABLISHED and AUTHORIZED tiers in the same query shape. If EQL's ESTABLISHED query can return authorization-grade data, the tier distinction is decorative in the query language even if enforced in the store. **Introduce a fourth query tier, or require a separate `AUTHORIZE` clause that forces the `au` evaluator round.**

**NEW-5. Performance claims and security claims are mutually attacking.**
Idea #1 says weights "only control traversal priority." Idea #2 says retraction is O(1). Idea #4 says low-trust queries are "fast." Every performance claim assumes *caching* of derived state; every security claim assumes *freshness* of derived state. These cannot both be true without naming the cache invalidation mechanism *and its cost*. The design uses "fast" and "O(1)" as if they were free; under adversarial scheduling they are the seams.

**NEW-6. The doctrine list itself is missing a rule.**
Doctrine #4: multiple attestations ≠ independent. But there is no doctrine for *compositional risk*: a chain of individually-acceptable witnesses can produce an unacceptable joint confidence. This is exactly #12's ghost clumping + weak witness under policy composition, and it is exactly #10's weight laundering across hops. TIG has no *composition* doctrine, only per-edge doctrines. **Add doctrine #6: no composite establishment may claim stronger trust than the weakest link in its witness-independence chain, and the chain must be tracked, not assumed.**

VERDICT: TIG's ontology survives; its *operational* claims (O(1) retraction, same-clock-cycle lease death, weight-as-priority-only, EQL tier enforcement, au-supplied-subgraphs) are all either theater or doctrine-#1 replay points, and the design has no compositional-trust or freshness-for-derived-state doctrine to close them.
